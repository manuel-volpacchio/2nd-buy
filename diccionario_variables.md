# Diccionario de variables - REBUY v2

Clasificacion por temporalidad y riesgo de leakage. Grupo A = seguro para prediccion (disponible al momento de trip1). Grupo B = post-trip1 con ventana controlable. Grupo C = leakage directo del target, nunca usar como feature. Grupo D = descriptivo, cobertura/temporalidad no resuelta.

| Variable | Grupo | Fuente | Usable en modelo | Nota |
|---|---|---|---|---|
| social_id | id | grano | False | Identificador de usuario, no es feature. |
| fecha_primer_trip | A | clientes_trips_fact | solo como ancla temporal (cohorte), no como feature del modelo | Define la cohorte y el punto t=0 de toda ventana. |
| fecha_segundo_trip | C | clientes_trips_fact | False | Es el evento objetivo. Nunca se usa como feature. |
| pais | A | clientes_trips_fact (trip1) | True |  |
| purchase_type / product_type (trip1) | A | clientes_trips_fact (trip1) | True | Producto principal de la transaccion representativa de trip1. |
| plataforma_trip_1 | A | mkt_users_fact_transactions | True | Puede ser multivalor si trip1 tuvo mas de una transaccion en plataformas distintas. |
| canales_compra_trip_1 | A | mkt_users_fact_transactions | True | Idem, multivalor posible. |
| origen_trip / destino_trip | A | clientes_trips_fact (trip1) | True | Alta cardinalidad; usar con agrupamientos (region/top aeropuertos). |
| flight_class (trip1) | A | bi_transactional_fact_segments | True | NULL estructural para no-Vuelos; no es missing real en ese caso. |
| flg_uso_cupon (trip1) | A | bi_transactional_fact_discounts | True |  |
| flg_uso_puntos / puntos_usados (trip1) | A | loy_redemption | True | Incidencia baja y creciente en el tiempo (ver disclaimer cobertura). |
| tier_al_momento_redencion (trip1) | A | loy_redemption | True | Solo no-nulo si hubo redencion de puntos en trip1 (~3% de las transacciones). |
| metodos_pago / flg_tarjeta_credito / flg_transferencia / etc. (trip1) | A | mkt_users_fact_payments + dim_payments | True | Cobertura ~97.5%; un 0 en flags especificos puede ser 'sin evidencia' mas que 'no usado' -- ver disclaimer cobertura Payments. |
| gross_bookings_usd / net_revenues_usd / cost_usd / fee_net_usd (trip1, sumado por transaction_code) | A | mkt_users_fact_transactions | True | Cobertura completa 2020+. Existen valores negativos (refunds/ajustes, <1%) y ceros (~0.07%). |
| margin_variable_usd / npv_usd (trip1) | A | mkt_users_fact_transactions | solo cohortes 2020+ | 100% NULL en 2019 (no existia el calculo). Excluir 2019 de cualquier analisis de margen/NPV. |
| eventos_directo/seo/meta/crm/otros, eventos_path_total (trip1) | A | bi_mkt_fact_attributed_sales (model_id=33) | solo cohortes 2021+ | 0% de cobertura en 2019-2020 (el modelo de atribucion no existia todavia). Es el path de ESA compra, no historial de exposicion del usuario. |
| first_click / last_click datetime y event_type (trip1) | A | bi_mkt_fact_attributed_sales (model_id=33) | descriptivo, cohortes 2021+ (no incluido en el modelo) | Mismo patron de cobertura que eventos_*. Se usa en el dashboard (seccion Path de medios) reclasificando event_type con la misma taxonomia Directo/CRM/SEM-SEO-KWBrand/Metabuscadores/Otros: CRM es el canal con mayor recompra asociada tanto de first-click como de last-click (~26.8%), Metabuscadores el menor (~16%). Los journeys con first y last click de canal distinto (multi-touch) recompran mas (24.8%) que los de un solo canal (21.6%). No se uso como feature del modelo por el mismo riesgo de confusion con cohort_year que eventos_*. |
| flg_app_90d_antes_trip1 / visitas_app_90d_antes_trip1 | A | mkt_users_fact_visits (App) | True | Incidencia creciente 2019->2025 (18%->57%): correlaciona con adopcion de la app en el tiempo, no solo con el usuario. SIEMPRE controlar por cohort_year. |
| ultima_visita_app_antes_trip1 | A | mkt_users_fact_visits (App) | True | Se puede derivar dias desde ultima visita a trip1. |
| tipo_viaje (Nac/Int) | A | sin documentar (nuevo) | True | 0% NULL. 99.2% consistente dentro de las transacciones de un mismo trip1 (se toma la de la transaccion mas temprana). |
| edad_aprox_primer_trip / rango_edad_primer_trip / birth_year | A | sin documentar (nuevo) | True | ~27% NULL en birth_year. PENDIENTE: el valor difiere entre la fila de trip1 y trip2 del mismo usuario en ~68% de los casos (incluso birth_year, que no deberia cambiar) -> parece ser un snapshot recalculado, no un dato fijo. Se usa el valor de la fila de trip1. |
| income | A | sin documentar (nuevo) | True | Categorico (Unknown/Low/Medium/High). ~9% NULL. Mismo caveat de snapshot que birth_year/nationality. |
| nationality / pais_residencia / estado_residencia / ciudad_residencia | A | sin documentar (nuevo) | nationality y pais_residencia si; ciudad muy alta cardinalidad, solo descriptivo | nationality ~30% NULL, ciudad_residencia ~34% NULL. Distinto de 'pais' (pais de la transaccion/viaje) -> permite separar de donde es el usuario de a donde viajo. Mismo caveat de snapshot. |
| antiguedad_usuario_dias_al_trip1 | A | sin documentar (nuevo) | True | ~0.3% NULL, muy buena cobertura. Por nombre esta ancaldo a trip1, pero igualmente difiere entre fila trip1/trip2 en ~72% de los casos -> mismo caveat de snapshot que el resto de estas variables nuevas. Se usa el valor de la fila de trip1. |
| geo_ultima_visita_ciudad/pais, geo_visita_frecuente_ciudad/pais, geo_ultima_transaccion_ciudad/pais | A | sin documentar (nuevo) | descriptivo, alta cardinalidad para modelo | Verificado que son snapshots que avanzan con el tiempo (difieren 71-72% entre fila trip1 y trip2 del mismo usuario) -> tomar SIEMPRE el valor de la fila de trip1 es seguro (representa el estado a esa fecha), nunca mezclar con la fila de trip2. |
| trip_checkin / trip_checkout / duracion_viaje_dias / bucket_duracion_viaje | A | sin documentar (nuevo) | True | 0% NULL. 99.85% consistente dentro de las transacciones de un mismo trip1. |
| dias_anticipacion_compra_checkin / bucket_anticipacion_compra | A | sin documentar (nuevo) | True | 0% NULL, pero SI varia entre transacciones del mismo trip1 (~10.4% de los trips tienen anticipacion distinta segun la transaccion, ej. vuelo comprado con anticipacion y un seguro agregado despues) -> se toma la anticipacion de la transaccion mas temprana de trip1 (la reserva principal). |
| dias_entre_trip_1_y_2 | C | sin documentar (nuevo) | False | Redundante con dias_a_recompra (calculado independientemente en este pipeline a partir de fecha_primer_trip/fecha_segundo_trip). Solo existe si ya hubo trip2 -> leakage directo, nunca se usa como feature. |
| flg_app_90d_post_trip1 / visitas_app_90d_post_trip1 | B | mkt_users_fact_visits (App) | solo subset no contaminado | CONTAMINADO para 31.5% de los recompradores (los que recompran <=90 dias): la ventana no se corta en fecha_segundo_trip. Se marca flg_contaminado_90d y se usa solo el subset limpio para el modelo/robustness check. No hay datos de visita individuales en el export para reconstruir una ventana exacta min(90d, trip2). |
| customer service (todas las variables cs_*) | D | as_omnichannel_fact_customer_experience | False | Sin timestamp de la interaccion en el export: no se puede saber si ocurrio antes o despues de trip2. Ademas cobertura estructuralmente distinta en el tiempo (~0% hasta 2023, 4.6-6.5% desde 2024). Se reporta solo como descriptivo, restringido a cohortes 2024+, nunca como feature predictiva. |
| cantidad_visitas_entre_trips / cantidad_searches_entre_trips | C | mkt_users_fact_visits | False | Ventana termina exactamente en fecha_segundo_trip -> solo existe para quien ya recompro. Util para analisis descriptivo 'entre recompradores', nunca como feature de prediccion de recompra. |
| flg_app_entre_trips / visitas_app_entre_trips / ultima_visita_app_antes_trip2 | C | mkt_users_fact_visits (App) | False | Mismo problema: solo definido para quien ya tuvo trip2. |
| plataforma_trip_2 / canales_compra_trip_2 / productos_trip_2 | C | trip2 | False | Es literalmente informacion del evento objetivo. |
| flg_mismo_producto_trip_1_2 | C | productos trip1 vs trip2 | False | Solo puede calcularse si trip2 ya ocurrio. |
| economics/loyalty/payments/cupon/CS/path de medios de trip2 (nro_trip=2) | C | transaction_code de trip2 | False | Es informacion de la transaccion que define el target. |
| eventos_crm (dentro de eventos_path_total) | D | bi_mkt_fact_attributed_sales | descriptivo, con cuidado | Es el path de ATRIBUCION de la compra, no el historial de envios/opens/clicks de CRM. La documentacion indica cobertura de mkt_users_fact_comms todavia sin cerrar -> no se construyen conclusiones fuertes de CRM historico en este entregable. |
